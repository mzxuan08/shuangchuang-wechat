# 双创团队公众号

为创新创业、科研与成果转化团队撰写正式、自然、有专业内容的公众号推文。突出真实贡献，减少防御性写作，兼顾完整报道与准确表达。

**只安装这一个技能即可。** 包内包含三个写作引擎和118篇样本的写法分析，不依赖 Codex、外部技能、模型品牌、脚本运行时或 API Key。

## 三个引擎，合在一个工作流程

| 引擎 | 实际作用 |
| --- | --- |
| 价值叙事与反防御 | 选择最有分量的成果，讲清优势与贡献；去掉无关的自我解释、过程流水账和主动示弱 |
| lieflat 轻清理 | 按11类可定位规则最小改动，保留原结构、全部信息和未命中句子 |
| qu-ai-wei 重写 | 用信息账本保护事实与逻辑，扫描八个模式族，在授权内调整全文组织与中文表达 |

新稿先建立成果主线，再做轻清理。普通“改一下、润色、顺稿”执行保义编辑，处理长导语、衔接与重复收尾；指定lieflat或白名单时才按严格边界清理，普通“去AI味”且无更宽要求时也沿用严格模式。正式题名、数字、引用与必要条件始终保护。事实核查在后台完成，默认交付标题与完整正文。

适用竞赛喜报、学术交流、项目进展、团队活动、阶段总结和科创深稿。原六篇范文提供目标语气与短稿、深稿方法；2.1版新增13篇、2.2版新增21篇、2.3版新增12篇、2.4版新增11篇、2.5版新增8篇、2.6版新增12篇、2.7版新增13篇、2.8版新增12篇、2.9版新增10篇已读正文的高校、医院报道及机构账号文章，学习库累计118篇，覆盖商会座谈、签约对接、竞赛路演、创业孵化、项目结题、社会实践与师生故事。来源见 [原样本](references/source-cards.md) 和 [扩展样本](references/expanded-sources.md)，能力对应见 [能力映射](references/capabilities.md)。

来稿中的“老师”等称谓默认保留。座谈稿按各方实际贡献写内容，交流意向与正式协议分别表达；团队故事保留真正解释方法形成的实践过程。叙事选择见 [座谈与对接写法](references/field-style.md) 和 [孵化与实践写法](references/practice-and-incubation.md)。新写孵化故事优先呈现实际进展，再解释具体支持；实践稿用对象、发现和动作推进，师生稿用真实互动呈现温度。

2.3版修正普通改稿被误判成白名单轻清理的问题：导语、重复内容和结尾都在常规编辑范围内。用户确认没有更多信息，就用已有事实交付，不以补案例为前提，不补造细节。指定保留结构时仍保留段落，指定局部修改时仍只改局部。实际改动说明按前后差异给出。

2.4版增加 [多项目与连续进展写法](references/progress-and-selection.md)：围绕本次新增动作选主次，区分旧合作、新合同及后续试用；展示、路演、发言、壁报和奖项分别对应，合同金额与到账金额各归其位，收尾落在实际内容上。

2.5版增加 [专业内容与人物声音](references/explanation-and-voice.md)：短讯用代表项目说明问题，技术解释接到使用环节，长稿围绕真实设计选择展开，师生各保留具体贡献；引语承载人物判断，小标题跟随内容变化。

2.6版补充 [团队账号的成稿落点](references/team-account-focus.md)，区分团队稿与组织方报道的重点。新增12篇中5篇可确认公众号来源，均通过可访问转载页读取正文，其他渠道逐篇标明。另公开 [8题复测试写](docs/evaluation-cases.md)：包含完整输入、当前模型交付样例、逐项核对与修订，方便直接检查效果；不把样本数量或构建成功当作写作质量证明。

2.7版新增13篇，含3篇明确标注公众号来源的转载、3篇“双创团队先锋录”专栏网页，以及年度总结、招新、入驻与答辩报道。学习落到现有指南中的参与条件、两类读者、年度统计和准确阶段。新增 [12种实际写稿场景](docs/scenario-suite.md)，与此前8题共20题；公开输入、当前模型成稿和逐题核对，未作独立盲测或跨宿主模型测试。

2.8版学习12篇团队成长、技术长稿和问答报道，修正“所有稿件都从结果起笔”的过度约束，并要求认识转折、段尾概括有对应材料。新增 [8种写稿与2道新题复核](docs/story-and-interview-cases.md)，连此前共30题，公开初稿问题、修订和成稿；保留试写中的篇幅不足，不把展示样例当作全部要求已通过。

2.9版新增10篇，学习具体协作、产品阶段、团队分工和学生自述。新增 [8种写稿与2道复核题](docs/revision-and-length-cases.md)，累计40题；延续上一轮年度材料并明确字数口径，正文达到426字符，产品稿和群像稿在修订后达到各自区间。事实复核同时处理回访归属、用途与已使用状态，以及相邻题细节串入，保留具体错误和修订记录。

## 下载

从 [Releases](https://github.com/mzxuan08/shuangchuang-wechat/releases/latest) 下载：

- `shuangchuang-wechat.zip`：通用 Agent Skills 包，适合 Codex、DSH 及支持标准 SKILL.md 的软件。
- `shuangchuang-wechat-workbuddy.zip`：WorkBuddy 上传包，补齐其开放平台要求的版本、作者和中英文描述字段；写作规则及参考文档与通用包一致。

不要把两个包同时安装到同一个宿主；选对应包即可。下载 GitHub 仓库源码也能使用，仓库根目录就是技能根目录。

## 安装

### Codex 与标准 Agent Skills 宿主

解压通用包，把整个 `shuangchuang-wechat` 文件夹放入宿主的技能目录。Codex 常用目录为 `~/.codex/skills/`。本技能不要求任何 Codex 专属工具；其他宿主按其本地技能目录安装。

### DSH

解压通用包，将文件夹放入用户级 `~/.dsh/skills/`，或项目级 `.dsh/skills/`，使入口成为 `skills/shuangchuang-wechat/SKILL.md`。名称保持 `shuangchuang-wechat`，不要把入口埋在多层目录中。按 [DSH 官方技能文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md) 的发现规则安装；使用自定义 DSH 主目录时以实际配置为准。

### WorkBuddy

在“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”中选择 `shuangchuang-wechat-workbuddy.zip`。安装后确认已启用，再在新对话中点名使用。步骤依据 [WorkBuddy 官方说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。

项目内也可按官方文档放入 `.codebuddy/skills/shuangchuang-wechat/`；见 [WorkBuddy 项目配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)。桌面个人库和云端个人库分别管理，需要在哪端使用就在哪端导入。

兼容规范和验证范围见 [兼容说明](docs/compatibility.md)。

## 直接使用

> 用双创团队公众号技能，根据以下材料写一篇团队推文。突出最有价值的成果，正式自然，大幅减少防御性写作，只给标题和正文。

> 用 shuangchuang-wechat 修改这篇推文，理顺导语和各方发言，精简重复收尾，保留老师称呼。没有更多信息，请只依据现有内容改。

> 用 shuangchuang-wechat 轻清理这篇稿子，保留段落、题名、数字和未命中的句子。

> 用 shuangchuang-wechat 的 qu-ai-wei 模式重写这篇推文，可以调整段落，保留所有独立事实和限定。

支持 `$技能名` 的宿主也可使用 `$shuangchuang-wechat`。其他软件可直接点名或从技能菜单选择，不依赖这一语法。

最好提供团队名称、活动与项目资料、角色分工、正式结果、已有数据及确定的后续安排。缺项不需要逐一填表；技能按可成立的主线先写。材料只够简讯时就写简讯。

## 文件

`SKILL.md` 是唯一入口。`references/` 包含写法分析、体裁指南、反防御、编辑规则、事实边界与示例；其中 `upstream/` 保存两套完整编辑规则和许可证。`agents/openai.yaml` 是可选的 Codex 界面配置，其他宿主可忽略。`tools/` 仅用于维护者构建、校验发行包，不参与写稿。
