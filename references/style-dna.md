# 写法与语气

## 这套风格来自哪里

样本为用户提供的六个本地微信 HTML，编号见 [来源卡片](source-cards.md)。S1、S2、S3、S5、S6 是“太和护理”发布的短篇机构报道，正文以自然段推进；S4 是“武汉市科技创新服务中心”转发的《瞭望》科创报道，篇幅、采访密度、观察尺度均不同。以下是对这组材料的编辑归纳，不是公众号行业统一标准，也未把样本文中事实当作外部已核验结论。

2.1版补充13篇、2.2版补充21篇、2.3版补充12篇、2.4版补充11篇、2.5版补充8篇、2.6版补充12篇、2.7版补充13篇已读取正文的高校、医院报道及机构账号文章，累计96篇样本，覆盖商会座谈、校企签约、成果对接、路演备赛、创业孵化、项目结题、社会实践与师生故事。来源、可见发布日期和阅读状态见 [扩展卡片](expanded-sources.md)。原六篇用于维持目标语体，扩展样本用于选择更贴近事件的组织方式，二者不合并成万能模板。

## 继承的写法

| 观察 | 样本依据 | 双创团队的用法 |
| --- | --- | --- |
| 结果前置 | S1首段写两项荣誉；S6首段写本届结果及连续获奖记录 | 导语写获奖、入围、发言或阶段进展，动作名称准确 |
| 主体持续出现 | 多篇反复点明团队、科室、发言者及题目 | 团队名承担主体；需要区分贡献时写个人、合作单位，不用泛称遮盖归属 |
| 项目有专业内容 | S1从转运问题解释系统做法和应用；S6分别交代两个案例的专业重点 | 让读者明白项目解决什么、关键做法是什么、证据到哪一步 |
| 多事项各成单元 | S2按会议分段；S3把近期交流与全年记录分开 | 选会议、时间或成果类型中的一个尺度排序，单元内部保留差异 |
| 首尾呼应 | 五篇短稿均从事件回到专科实践或服务方向 | 收束回应本次项目；下一步只写已有计划，事实够清楚也可直接结束 |
| 深稿由小见大 | S4从晶圆、产业楼、交易大厅等具体对象进入，再写平台和机制 | 有采访和材料时，从一个真实项目现场解释需求、技术、协作或转化路径 |
| 机构语气稳定 | 使用第三人称与专业名词，题名用书名号，活动名写全 | 正式但不写成文件；少聊天称呼，避免口语化改写专业术语 |

## 标题怎样学

- **结果型**：主体＋赛事/平台＋具体结果。S1强调“两项奖项”，S6强调“连续三年”，两者都靠事实支撑标题。
- **交流型**：主体＋发言、展示或交流平台。S2标题直接；S3、S5增加主题句再接事件说明。
- **深度型**：明确议题或变化，让正文解释机制。S4聚焦区域科创，不能把宏观建设任务原样换成学生团队口号。

主题短句、感叹号和破折号在这组样本中有用途，可按需要保留；不要规定“所有标题必须对仗”“必须喜报”“必须双标题”。项目名很长时标题可用不歧义的简称，正文首次列全名。不可为追求简短改变赛事、奖项和研究题名的正式名称。

## 导语与主体怎样接

短稿导语承担新闻交代，第二段开始补足读者理解结果需要的信息。S1“事件与两项荣誉→赛事背景→项目与应用→专业方向”，S2“多场交流总起→各会议分述→专科方向”。不要把前者的项目详解硬套给只有发言题目的简讯，也不要把后者写成重复的三段“精彩亮相”。

项目解释优先用可核对的主干：

> 对象面临什么问题；团队采用什么方法；目前取得什么进展。

这是组织材料的方法，不要求缺失项必须补齐。只有项目题名时，可写发言主题和场合；没有研究结果时不从题名推导干预有效。

## 语气的分寸

整体语气正式、积极、主动交代成果。像这组机构报道一样，让团队做了什么、项目有什么价值站到前面。可以适度祝贺、使用有内容的主题短句，结尾回应专业方向；必要范围融进结果句，不另起自我审查段。面向真实受众解释项目，不用论文评审式口吻先列一串尚未完成事项。

允许适度祝贺与积极评价，但一个事实段不必都配一句“充分彰显”“生动诠释”。新增稿中优先写“获一等奖”“完成原型”“作专题发言”等具体动作；“得到高度认可”须有真实评价或可说明的结果，不由登台事实自动推出。

“赋能、深耕、突破、创新、聚焦”等不是禁词。判断整句是否提供信息，避免机械替换成口语。正式称谓和专业表达可以重复；用代词会混淆项目与团队时，宁可再次点明。

来稿中已有的“老师”等称呼保留，不把校园语境的礼貌视为 AI 痕迹。正式题名、机构理念、真实评价与判断强度同样受保护；不要为了显得克制，机械删掉“重要”“充分”等评价词。具体编辑幅度按任务授权决定。

样本常用的“在院党委的坚强领导下”“新业态护理”“智慧化、专业化、全程化、人文化”承载医院自身身份和业务方向。只有本团队确有该关系、正式表述且与当前稿件有关时才使用。学生团队、科研团队和企业团队各按已知身份写，不能默认互换。

## 需要筛掉的样本噪声

- S1正文“近日”被 HTML 样式切成“近”和“日”；S6机构全称也被样式切断。提取时恢复连续文本，不把换行当自然段。
- S5存在“分享分享”的重复字词。这是校对问题，不作为模仿特征。
- S3不同位置的会议/分会称谓存在写法差异。真实写稿须据邀请函、议程或用户确认核对，不根据语感发明正式名称。
- S1同时报告“准备时长缩短60%”与“效率提升60%”。这是两个原文指标；不能视为同一指标的自动换算，也不能移植到别的项目。
- S4末尾的往期推文标题、投稿邮箱、版权说明属于页面附属区；区分正文、图片说明、来源与相关推荐。新闻正文不照抄推荐链接。
- 样本里的宏大结尾、反复“既是……更是……”和泛化赞誉可用于识别目标语体，不应成为新稿的固定模板。编辑现有原文时仍遵守保义和受保护片段要求。

## 结合以往正式报道经验

“总起—分述—回扣”可帮助短篇消息完整成篇，但不是所有稿件的硬性三段式。活动方案、教案或未来计划不能写成现场已发生事项；未提供班级、单位、导师或领导姓名不代填；结尾有始有终，也不能为了完整编造下一步行动。这些是写作约定，不是六篇样本逐篇证明的规律。
